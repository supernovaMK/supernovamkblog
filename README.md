# supernova.log

마크다운으로 쓰고 GitHub Pages로 배포하는 개인 블로그입니다.
프레임워크 없이 Node.js 빌드 스크립트 하나로 정적 HTML을 만듭니다.

- **글쓰기** → `posts/` 폴더에 마크다운 파일 하나
- **내 정보 수정** → `src/config.js` 한 파일
- **배포** → `git push` (나머지는 GitHub Actions가 알아서)

---

## 1. 처음 한 번만 하는 준비

### 의존성 설치

```bash
npm install
```

### GitHub Pages 켜기

1. GitHub 저장소 → **Settings** → **Pages** 로 갑니다.
2. **Source** 를 **GitHub Actions** 로 바꿉니다. (`Deploy from a branch` 아님)
3. 끝입니다. 이제 `main` 에 push할 때마다 자동으로 배포됩니다.

배포 주소는 **https://supernovamk.github.io/supernovamkblog** 입니다.

---

## 2. 글 올리는 법 — 클로드에게 맡기기

가장 편한 방법입니다. **마크다운만 쓰고 나머지는 넘기면 됩니다.**

이 저장소를 연 상태에서 이렇게 말하세요.

> 새 글 올려줘. 제목은 "인덱스 하나로 응답이 10배 빨라진 이유", 태그는 데이터베이스랑 회고.
> (그 아래 본문 마크다운 붙여넣기)

그러면 클로드가 알아서 합니다.

1. `posts/2026-08-01-제목.md` 파일을 만들고 frontmatter를 채웁니다
2. `npm run build` 로 깨지는 곳이 없는지 확인합니다
3. 커밋하고 push 합니다 → 1~2분 뒤 사이트에 반영

**파일로 건네도 됩니다.** `.md` 파일을 저장소 아무 데나 두고 "이거 올려줘" 라고만 하세요.

몇 가지 알아두면 좋은 것:

- **초안으로 두고 싶을 때** — "초안으로만 만들어줘" 라고 하면 `draft: true` 상태로 두고 push하지 않습니다
- **push는 확인 후에** — 커밋·push 전에 한 번 물어보게 되어 있습니다. 바로 올리고 싶으면 "확인 없이 바로 올려줘" 라고 하세요
- **고칠 때도 마찬가지** — "지난번 인덱스 글에 문단 하나 추가해줘" 처럼 말하면 됩니다
- **지도에 연결** — "이 글을 스킬맵 Docker 지점에 연결해줘" 라고 하면 `src/config.js` 의 해당 지점 `post` 값까지 채워줍니다

아래 3번은 직접 하고 싶을 때 보는 내용입니다.

## 3. 글 쓰는 법 — 직접 하기

### ① 새 글 만들기

```bash
npm run new "첫 글을 씁니다"
```

`posts/2026-08-01-첫-글을-씁니다.md` 파일이 만들어집니다.
주소를 영어로 하고 싶으면:

```bash
npm run new "첫 글을 씁니다" -- --slug hello-world
```

> 파일을 직접 만들어도 됩니다. 이름만 `YYYY-MM-DD-주소.md` 형태면 됩니다.

### ② 글 쓰기

파일을 열면 맨 위에 이런 게 있습니다. 이걸 **frontmatter** 라고 부르고,
`---` 와 `---` 사이는 글 내용이 아니라 글에 대한 정보입니다.

```markdown
---
title: "첫 글을 씁니다"
date: 2026-08-01
summary: "목록에 보일 한두 줄 요약입니다."
tags: ["회고", "javascript"]
draft: true
---

여기서부터 본문입니다.
```

| 항목 | 설명 |
| --- | --- |
| `title` | 글 제목. **따옴표로 감싸주세요** (`:` 같은 문자가 들어가면 깨집니다) |
| `date` | 발행일. `2026-08-01` 형식 |
| `summary` | 목록에 보일 요약. 비워두면 본문 앞부분을 자동으로 씁니다 |
| `tags` | `["태그1", "태그2"]`. 없으면 `[]` 로 두세요 |
| `draft` | `true` 면 사이트에 안 나옵니다. 다 쓰면 이 줄을 **지우세요** |

### ③ 눈으로 확인하기

```bash
npm run dev
```

브라우저에서 **http://localhost:3000** 을 엽니다.
파일을 저장하면 자동으로 다시 만들어지니, 브라우저만 새로고침하면 됩니다.

### ④ 발행하기

`draft: true` 줄을 지운 다음:

```bash
git add . && git commit -m "새 글: 첫 글을 씁니다" && git push
```

1~2분 뒤 사이트에 올라갑니다. 진행 상황은 저장소 **Actions** 탭에서 볼 수 있습니다.

## 4. 마크다운 문법 (자주 쓰는 것만)

```markdown
## 큰 제목          ← 글 안에서는 h1(#) 말고 h2(##)부터 쓰세요
### 작은 제목

**굵게**, *기울임*, `코드`, ~~취소선~~

- 목록
- 목록
  - 들여쓴 목록

1. 번호 목록
2. 번호 목록

[링크 이름](https://example.com)

> 인용문입니다.

| 항목 | 값 |
| --- | --- |
| 속도 | 빠름 |

---   ← 구분선
```

**코드 블록**은 백틱 세 개로 감싸고 언어 이름을 적으면 색이 입혀집니다.

````markdown
```js
const hello = () => console.log('안녕');
```
````

**이미지**는 `posts/images/` 폴더에 넣고 이렇게 부릅니다.

```markdown
![사진 설명](/images/파일이름.png)
```

몇 가지 편의 기능이 자동으로 붙습니다.

- 엔터 한 번만 쳐도 줄바꿈이 됩니다
- 소제목이 3개 이상이면 글 위에 목차가 생깁니다
- 코드 블록에 마우스를 올리면 복사 버튼이 나옵니다
- 바깥 사이트 링크는 새 탭에서 열립니다

## 5. 내 정보 바꾸기

`src/config.js` 파일 하나만 고치면 됩니다. 열어보면 주석이 달려 있습니다.

| 고치고 싶은 것 | 위치 |
| --- | --- |
| 블로그 이름, 설명 | `site` |
| 첫 화면 인사말, 한 줄 소개 | `hero` |
| "저는 이런 사람입니다" 내용 | `about` |
| "제가 요즘 하고 있는 것은…" 목록 | `now` |
| GitHub·이메일 등 링크 | `socials` |
| 상단 메뉴 | `nav` |
| 스크롤 내리면 나오는 지도 | `skillMap` |

`now.items` 의 `status` 는 세 가지 중 하나입니다.

- `'active'` — 초록 점, "진행 중"
- `'exploring'` — 주황 점, "살펴보는 중"
- `'paused'` — 회색 점, "잠시 멈춤"

색이나 여백을 바꾸고 싶으면 `src/assets/style.css` 맨 위 `:root` 의 변수만
건드려도 분위기가 꽤 달라집니다. 색은 구글 팔레트(`--blue` `--red` `--yellow` `--green`)를
쓰고 있고, 지도 색은 `--map-*` 변수에 따로 모여 있습니다.

## 6. 스킬 맵 고치기

첫 화면을 스크롤해서 내리면 나오는 구글 맵 스타일 지도입니다.
`src/config.js` 의 `skillMap` 에서 고칩니다.

```js
nodes: [
  {
    id: 'docker',           // 겹치지 않는 아무 이름
    label: 'Docker',        // 지도에 뜨는 이름
    x: 840, y: 360,         // 지도 위 자리
    title: '내 컴퓨터에서는 되는데요',   // 왼쪽 카드 제목
    summary: '...',         // 카드 설명
    tech: ['Docker', 'CI/CD'],         // 칩으로 표시됩니다
    post: 'my-docker-post', // 이 글로 가는 버튼이 생깁니다. 없으면 ''
  },
]
```

**좌표 규칙 세 가지만 지키면 됩니다.**

1. 지도는 가로 1240 × 세로 640 입니다. (왼쪽 위가 `0, 0`)
2. **x는 490보다 크게** 두세요. 그보다 왼쪽은 정보 패널에 가려집니다.
3. 이웃한 지점끼리는 **x가 같거나 y가 같아야** 합니다.
   길이 가로·세로로만 이어지기 때문입니다. (도로 위를 지나가야 자연스럽습니다)

`post` 에 글 주소(slug)를 적으면 그 지점 카드에 **글 읽기** 버튼이 생기고,
읽는 데 걸리는 시간도 자동으로 붙습니다. 비워두면 "글 준비 중"으로 표시됩니다.

`areas` 는 지도에 흐리게 깔리는 동네 이름이고, 지점과 겹치지 않는 자리에 두면 됩니다.

## 7. 폴더 구조

```
posts/              ← 글을 쓰는 곳 (여기만 자주 열게 됩니다)
  images/           ← 글에 넣을 이미지
src/
  config.js         ← 내 정보 (두 번째로 자주 여는 파일)
  build.js          ← 빌드 스크립트
  markdown.js       ← 마크다운 → HTML 변환
  helpers.js        ← 날짜·주소 같은 잔일
  new-post.js       ← npm run new
  dev.js            ← npm run dev
  templates/
    home.js         ← 첫 화면 (인사 + 최신 글 + 요즘 하는 것)
    skill-map.js    ← 스크롤하면 나오는 지도 (SVG를 여기서 그립니다)
    post.js         ← 글 본문 / post-list.js, about.js, layout.js …
  assets/
    style.css       ← 디자인 (구글 팔레트)
    app.js          ← 다크모드·지도 조작·검색·복사버튼
dist/               ← 빌드 결과 (자동 생성, git에 안 올라감)
```

## 명령어 정리

| 명령어 | 하는 일 |
| --- | --- |
| `npm run new "제목"` | 새 글 파일 만들기 |
| `npm run dev` | 로컬에서 미리보기 (localhost:3000) |
| `npm run build` | `dist/` 에 사이트 만들기 |

## 참고

- **주소를 짧게 하고 싶다면** — 저장소 이름을 `supernovaMK.github.io` 로 바꾸면
  `https://supernovamk.github.io` 가 됩니다. 배포 워크플로가 알아서 경로를 맞춥니다.
- **직접 산 도메인을 쓰고 싶다면** — Settings → Pages 에서 Custom domain 을 설정하고,
  `src/config.js` 의 `site.url` 과 `site.basePath`(빈 문자열로) 를 맞춰주세요.
- **글이 안 보인다면** — `draft: true` 가 남아있는지, 파일 이름이
  `YYYY-MM-DD-` 로 시작하는지 확인해보세요.
